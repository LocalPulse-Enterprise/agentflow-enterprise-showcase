# FAQ

## What is AgentFlow Enterprise?

AgentFlow Enterprise is presented as an AI RevOps SaaS product for teams that need more structured revenue operations, clearer workflows, and AI-assisted operational execution.

## Is this the application source code?

No. This is a public showcase repository. It contains buyer-safe documentation only.

## Who should evaluate this repository?

Agencies, senior developers, RevOps consultants, technical buyers, investors, and potential acquirers can use this repository to understand the product positioning and diligence path.

## Does this repository include secrets or backend code?

No. It intentionally excludes secrets, environment files, backend logic, API route code, database schema, webhook handlers, checkout internals, and private implementation details.

## Can agencies use AgentFlow Enterprise with clients?

The product is positioned for agency and consultant evaluation. Commercial use, resale, white-labeling, client deployment, or licensing should be discussed directly with the owner.

## Is AgentFlow Enterprise production verified?

This repository does not claim full production verification. Any production readiness, integration behavior, security status, and operational maturity should be confirmed through private diligence.

## Does AgentFlow Enterprise claim SOC 2, ISO 27001, HIPAA, or other certifications?

No. This repository does not claim external security or compliance certifications.

## Can developers review the technical architecture?

Developers can review the high-level technical due diligence notes in this repository. Private technical review may be made available under appropriate access controls and confidentiality terms.

## Does this repository reveal API routes or database tables?

No. It deliberately avoids route names, database structure, implementation details, webhook logic, and other information that could increase security risk.

## Can non-technical buyers understand the product from this repository?

Yes. The documentation is written to be clear for non-technical buyers while still giving technical reviewers enough structure to know what to ask during private diligence.

## Are there real customer, revenue, or usage claims?

No. This repository avoids unverified customer logos, testimonials, revenue claims, usage metrics, or adoption claims.

## How can an interested buyer start diligence?

Use the contact paths in [CONTACT.md](CONTACT.md). A private review can be discussed for qualified acquisition, partnership, or licensing conversations.
